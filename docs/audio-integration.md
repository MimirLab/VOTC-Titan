# Breeze character audio

Titan's main audio path is **your connected text model → saved character voice design → Breeze speech**. The text model receives the selected character persona, player-authored portrayal, verified body/race and resolved lore, plus ready culture and faith guidance. It designs the stable voice once. The local voice library reuses that identity, seed and original generated reference recording. Any configured text provider can do this; “Mimir” in the study receipts identifies the particular attached model used for those studies.

## Using Audio

Open **Audio** in either settings window. Audio starts disabled. Choose **Breeze**, select local hosting or an external Breeze endpoint, and save settings. Local model downloads are explicit; the app does not download or load a voice model at startup. Use **Download**, then **Start / test Breeze** and **Preview narrator** to check the selected package. Enable character audio when ready.

AI dialogue plays automatically after its text has been committed. First use prepares the character's actual voice; text remains available while voice preparation runs. Visible internal thoughts whisper by default. Narration and typed player speech are separate opt-ins. This voices Titan conversation participants, including group exchanges and NPC-to-NPC replies that the player actually receives. Microphone input and native CK3 event/tooltip dubbing are outside this release.

The chat has pause, stop and per-message replay controls. Edits, undo, regeneration, cancellation, encounter closure and campaign changes discard queued playback. Explicit historical replay uses the player's recorded literary reading. Audio errors leave committed text available, with a status explaining the problem.

Saved voices appear in Audio. You can preview them, edit the voice instruction into a new revision, or redesign a current participant with the connected text model. Existing delivery receipts preserve their original voice revision and maturity instruction; future replies use the new revision. A single global narrator remains consistent across campaigns.

Optional compatible speech and ElevenLabs connections are side adapters using provider voice IDs. They do not replace Breeze's prompted-character design system and are never automatic fallbacks. The ElevenLabs adapter leaves thoughts in text because it cannot honor this pipeline's whisper instruction. Preview tests the chosen optional connection.

Vulkan packages include a checked 72.2 MB runtime. CUDA installation includes codec/tokenizer/config files, an isolated managed Python environment and additional dependencies. The environment's resolved dependency lock is retained. Downloaded archives and model files are pinned by revision, size and SHA-256; interrupted model downloads resume and are verified before use. Original reference WAVs and transcripts remain durable, while codec bindings are runtime/model-specific caches that can be rebuilt after a server restart.

The local manager owns a loopback-only server and unloads it after the configured idle period. Explicit unload and cancellation controls are available. Managed Vulkan hosting requires a usable GPU and verifies the server's actual Vulkan backend; CPU fallback is disabled. A verified single discrete GPU uses a 2 GiB available system-RAM budget, with separate 6 GiB Q8 / 9 GiB F16 free-VRAM checks. Unknown/shared/ambiguous memory reporting retains the conservative 5/8 GiB RAM budgets and still requires GPU execution. An already installed Q8 can be selected automatically when the preferred package cannot fit or start; no download starts automatically. A live listener on the local port is never adopted as an owned server. CUDA packages require NVIDIA hardware and their configured memory budget before downloading. Download size alone does not establish peak memory. No root, Steam, swap, driver or frozen Wine changes are made.

## Identity, age and delivery

The current voice-design request asks for individual texture, articulation and habitual cadence, without current age or temporary emotion. The acoustic composer supplies authored anatomy and learned accent directly to Breeze after that separate text-model request; see [acoustic casting](audio-casting.md). The attached text model also supplies the existing bounded whole-reply delivery cue only when audio is enabled. Code handles current maturity, thought whispering, narrator routing and playback order. Missing or invalid optional cues become neutral delivery and never justify an extra roleplay request by themselves.

Current age is evaluated at delivery time, preferring an actual birth date. Captured integer age advances by complete elapsed years when only that value is available. Human stages are very young child (<6), child (<13), adolescent (<18), young adult (<30), adult (<55), older adult (<70), then elderly. These are qualitative voice directions, not a yearly voice redesign or pitch-shifting formula. Children progress into adulthood even when they later become ageless. Verified ageless adults keep their adult voice; verified long-lived people receive “age slowly” guidance. Unknown racial maturity scales are not invented. Later game dates do not reinterpret already recorded deliveries.

The library keys character voices by verified campaign identity and character ID, never a mutable name. It is an audio library for encountered characters; it adds no world scan, study bank, language fluency or NPC study tracking.

## Literary and privacy boundaries

Speech synthesis receives only the player's frozen delivered literary reading. It does not receive hidden canonical English behind FAR/CLOSE masks. Existing language routing, productive bridges, independent vocabularies, frozen hearings and scoped echoes remain authoritative. Private thought ownership is inherited from the delivered projection; audio does not infer or reveal another participant's hidden thoughts.

Audio cues are removed before prose validation and canonical persistence. They are kept out of displayed text, conversation stores, summaries, diaries, memory and embedding inputs. The library stores voice identity and compact delivery receipts, not a second prose history. Audio API keys are available only through the owned Audio settings page; ordinary configuration reads redact them. Audio disabled retains the original roleplay prompt/request and streaming paths and starts no voice job.
